# Как выложить сайт на GitHub и открыть его в интернете

Инструкция рассчитана на Windows и на то, что вы раньше с GitHub не работали. Займёт 20–30 минут. На выходе сайт будет открываться по адресу вида `https://ваш-логин.github.io/klevtsov-studio/` — бесплатно, с HTTPS, без хостинга.

Названия кнопок в интерфейсе GitHub иногда меняются. Если что-то называется немного иначе, ищите по смыслу — логика шагов остаётся той же.

---

## Что понадобится

- Архив **`klevtsov-site-git.zip`** — версия с историей правок. Именно её, а не `klevtsov-site.zip`.
- Почта для регистрации на GitHub.
- Файл `САЙТ-открыть-двойным-кликом.html` на GitHub **не загружается** — он только для просмотра у себя на компьютере.

---

## Шаг 1. Регистрация на GitHub

1. Откройте [github.com](https://github.com) и нажмите **Sign up**.
2. Введите почту, придумайте пароль и **логин**. Логин войдёт в адрес сайта, поэтому выбирайте короткий и понятный, например `klevtsov-studio` или `dklevtsov`.
3. Подтвердите почту кодом из письма.
4. На вопросы анкеты можно ответить как угодно или пропустить. Тариф — **Free**.

Логин запишите — он понадобится дальше.

---

## Шаг 2. Распакуйте архив

1. Нажмите правой кнопкой на `klevtsov-site-git.zip` → **Извлечь всё** → **Извлечь**.
2. Появится папка `klevtsov-site`. Откройте её — внутри должны быть `index.html`, папки `models`, `img`, `vendor` и другие файлы.

Внутри лежит скрытая папка `.git` с историей правок. Её не видно, если в проводнике не включён показ скрытых файлов, — это нормально, ничего делать с ней не нужно.

**Важно:** запомните, где лежит эта папка. Лучше перенести её в простое место, например `C:\Сайт\klevtsov-site`. Не держите её в «Загрузках» — её легко случайно удалить.

---

## Шаг 3. Загрузка на GitHub

Есть три способа. **Рекомендую первый** — он самый простой и сохраняет историю правок.

### Способ А. Через программу GitHub Desktop — рекомендую

Программа с обычными кнопками, без командной строки.

**Установка**

1. Скачайте с [desktop.github.com](https://desktop.github.com) и установите.
2. При первом запуске нажмите **Sign in to GitHub.com**, в браузере подтвердите вход.
3. На шаге настройки Git оставьте имя и почту, которые программа предложит, → **Finish**.

**Добавление сайта**

1. В меню: **File → Add local repository**.
2. Нажмите **Choose…** и выберите папку `klevtsov-site`, ту, внутри которой лежит `index.html`.
3. Нажмите **Add repository**. Слева появится список коммитов — это история правок сайта.

   Если программа пишет «This directory does not appear to be a Git repository», значит выбрана не та папка: вероятно, на уровень выше. Выберите именно ту, где лежит `index.html`.

**Публикация**

1. Вверху нажмите **Publish repository**.
2. Заполните окно:
   - **Name** — `klevtsov-studio` (войдёт в адрес сайта; латиница, без пробелов);
   - **Description** — можно оставить пустым;
   - **Keep this code private** — **снимите галочку**. Почему — объяснено ниже, в разделе «Публичный или приватный».
3. Нажмите **Publish repository** и дождитесь окончания загрузки, это около минуты.

Готово — переходите к шагу 4.

### Способ Б. Через браузер, без программ

Подходит, если не хочется ничего устанавливать. Минус — история правок не сохранится, будет только текущая версия.

1. На GitHub нажмите **+** в правом верхнем углу → **New repository**.
2. **Repository name** — `klevtsov-studio`, выберите **Public**, галочки ниже не ставьте. Нажмите **Create repository**.
3. На открывшейся странице найдите ссылку **uploading an existing file** и нажмите на неё.
4. Откройте папку `klevtsov-site` в проводнике, выделите **всё содержимое** (Ctrl+A) и перетащите в окно браузера.

   Перетаскивать нужно содержимое папки, а не саму папку, — иначе сайт окажется внутри подпапки и не откроется по основному адресу.

5. Дождитесь, пока все файлы загрузятся — их около 50, внизу будет список.
6. Внизу нажмите **Commit changes**.

Если браузер не позволяет перетащить папки `models`, `img`, `vendor` целиком — загрузите их содержимое в несколько заходов через **Add file → Upload files**, сохраняя структуру папок.

### Способ В. Через командную строку

Для тех, кто работает с Git. Нужен установленный [Git for Windows](https://git-scm.com/download/win).

1. Создайте пустой репозиторий на GitHub, как в пункте 1–2 способа Б.
2. Откройте папку `klevtsov-site`, в адресной строке проводника наберите `cmd` и нажмите Enter.
3. Выполните по очереди, подставив свой логин:

```
git remote add origin https://github.com/ВАШ-ЛОГИН/klevtsov-studio.git
git branch -M main
git push -u origin main
```

При первой отправке откроется окно входа в GitHub — подтвердите вход в браузере.

---

## Шаг 4. Включение сайта — GitHub Pages

Репозиторий — это хранилище файлов. Чтобы он заработал как сайт, нужно включить GitHub Pages.

1. Откройте репозиторий на GitHub: `https://github.com/ВАШ-ЛОГИН/klevtsov-studio`.
   Из GitHub Desktop туда ведёт кнопка **View on GitHub**.
2. Вверху нажмите **Settings** (значок шестерёнки).
3. В меню слева найдите **Pages**.
4. В разделе **Build and deployment**:
   - **Source** — `Deploy from a branch`;
   - **Branch** — `main`, папка `/ (root)`;
   - нажмите **Save**.
5. Подождите 1–3 минуты и обновите страницу. Вверху появится строка **Your site is live at** со ссылкой.

Адрес будет таким:

```
https://ВАШ-ЛОГИН.github.io/klevtsov-studio/
```

Откройте его — сайт должен загрузиться.

## Шаг 5. Проверка

Откройте сайт и пройдитесь по списку. Лучше проверить и на компьютере, и на телефоне.

- [ ] Первый экран: знак собирается, вокруг вращаются детали.
- [ ] Кейсы: во вкладке «3D-модель» модель загружается и вращается мышью. Здесь, в отличие от файла с диска, модели должны работать.
- [ ] Вкладки «Чертёж», «Производство», «Изделие» показывают картинки.
- [ ] Отзывы: по клику на «Открыть письмо» письмо открывается целиком.
- [ ] Калькулятор считает, кнопка «Перенести в заявку» заполняет форму.
- [ ] **Форма**: отправьте тестовую заявку — она должна прийти в Telegram. Если выдаёт ошибку, см. «Частые проблемы».
- [ ] Меню на телефоне открывается, ссылки ведут к нужным разделам.
- [ ] Страница «30 стадий» открывается по ссылке из блока «Процесс».

## Шаг 6. Как вносить правки потом

### Через GitHub Desktop

1. Откройте папку `klevtsov-site`, внесите правки в файлы. Например, замените фото в `img` или поправьте текст в `index.html`.
2. Переключитесь в GitHub Desktop — слева появится список изменённых файлов.
3. Внизу слева в поле **Summary** коротко опишите, что поменяли, например «Новый кейс с конвейером».
4. Нажмите **Commit to main**, затем вверху **Push origin**.
5. Через 1–2 минуты изменения появятся на сайте. Если не видно — обновите страницу с Ctrl+F5.

### Прямо в браузере

Небольшую правку текста можно сделать без программ: откройте файл на GitHub, нажмите значок карандаша **Edit**, поправьте, внизу **Commit changes**.

Все тексты сайта лежат в `index.html` в объекте `const SITE = {` — ищите через Ctrl+F.

## Шаг 7. Свой домен

Домен сайта — **`klevtsov-engineering.ru`**. Заглушки в файлах сайта уже заменены на него, и в корне репозитория лежит файл `CNAME` с этим адресом, — осталось настроить DNS у регистратора и включить домен в GitHub.

**У регистратора домена**, в настройках DNS, добавьте четыре записи типа **A** для самого домена (поле имени — `@`):

```
185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153
```

И одну запись типа **CNAME** для `www`, со значением `ВАШ-ЛОГИН.github.io`.

**На GitHub:** Settings → Pages → **Custom domain** → впишите домен → **Save**. Когда проверка пройдёт, поставьте галочку **Enforce HTTPS**. DNS обновляется от нескольких минут до суток — это нормально.

**После подключения домена** замените заглушку `https://klevtsov-engineering.ru` на свой адрес:
- в `index.html` — в `SITE.url` и в мета-тегах `canonical` и `og:` в начале файла (поиск по `klevtsov-engineering.ru`);
- в `robots.txt` и `sitemap.xml`;
- в `stages.html` и `privacy.html` — в теге `canonical`;
- в Cloudflare, в коде воркера: в блоке `CONFIG` в начале кода поле `origin` — вместо `'*'` впишите `'https://ваш-домен.ru'`, затем **Deploy**. Если адрес задавали через Settings → Variables and Secrets, правьте переменную `ALLOWED_ORIGIN` там.

## Публичный или приватный репозиторий

GitHub Pages бесплатно работает только с **публичными** репозиториями. Для приватного нужна подписка GitHub Pro — около 4 долларов в месяц.

Публичный репозиторий означает, что любой может открыть его и скачать все файлы сайта, включая 3D-модели и чертежи. Но они и так доступны каждому посетителю сайта: модель, которую браузер показывает, браузер же и скачивает. Так что публичный репозиторий на практике почти ничего не добавляет к тому, что уже видно на сайте.

Если какой-то проект нельзя показывать вообще — не держите его ни в репозитории, ни на сайте.

## Частые проблемы

**Открывается страница 404.**
Подождите 3–5 минут после включения Pages. Проверьте, что в Settings → Pages выбрана ветка `main` и папка `/ (root)`, а файл `index.html` лежит в корне репозитория, а не в подпапке `klevtsov-site`.

**Сайт открылся, но без стилей и картинок.**
Скорее всего, загружены не все папки. Проверьте в репозитории, что есть `img`, `models`, `vendor`, и внутри них файлы.

**3D-модели не загружаются, в окне модели надпись об ошибке.**
Проверьте, что в репозитории есть папка `models` с файлами `.glb` и папка `vendor/three`.

**Форма пишет «Отправка не прошла».**
Откройте адрес воркера в браузере — страница должна показать «BOT_TOKEN: задан». Если в воркере (поле `origin` в блоке `CONFIG`) уже вписан домен, а вы проверяете на адресе `github.io`, — временно поставьте туда `'*'` или `'https://ВАШ-ЛОГИН.github.io'`. Адрес пишется без пути, только до `.io`.

**Правки не видны на сайте.**
Подождите 1–2 минуты и обновите страницу с Ctrl+F5 — браузер мог показать старую версию из кэша. В репозитории на вкладке **Actions** видно, идёт ли публикация: жёлтый кружок — идёт, зелёная галочка — готово, красный крестик — ошибка.

**GitHub Desktop не видит папку как репозиторий.**
Выбрана не та папка. Нужна та, в которой лежит `index.html`. Если распаковывали не `klevtsov-site-git.zip`, а `klevtsov-site.zip` — в ней нет истории, используйте способ Б.
